# Telegram Book Downloader

Локальное нативное приложение на Rust для скачивания книг из Telegram-каналов
личного аккаунта. Целевые платформы: **macOS Apple Silicon** и **Windows 10/11 x64**.
GPUI рисует интерфейс непосредственно через платформенный backend:
WebView, Tauri, Electron, JavaScript, Docker и сервер приложению не нужны.

## Текущий статус

Реализован первый сценарий: авторизация → каналы → поиск вложений →
выбор книг и папки → последовательная очередь с прогрессом → локальная история.
Приложение запускает нативное окно, создаёт локальную SQLite
и обменивается типизированными командами/событиями между GPUI и Core на Tokio.
Первый запуск не требует credentials и не обращается к Telegram. Для входа
API ID/hash вводятся локально в интерфейсе. При наличии сохранённой сессии
приложение автоматически проверяет её через Telegram.

| Область | Что работает |
| --- | --- |
| Workspace | Пять crate приложения и Rust `xtask`, общие зависимости и линты, `Cargo.lock`, закреплённый stable Rust |
| UI | Тёмная оболочка в стиле Delta, сворачиваемый sidebar, Вход, Каналы, Загрузки, Библиотека, Настройки |
| Core ↔ GPUI | Ограниченные асинхронные каналы, обновление через `Entity::update` и `Context::notify` |
| Storage | SQLx, встроенные миграции, SQLite WAL, история, атомарная дедупликация и сохранение очереди |
| Downloader | Одна активная загрузка, потоковая запись, отмена, безопасные имена, no-clobber публикация |
| Очередь Core | FIFO до 256 ожидающих книг, группы в одну папку, пропуск повторов, пауза/продолжение, удаление заданий, восстановление на паузе после перезапуска |
| Telegram | Grammers 0.11: телефон → код → 2FA, восстановление сессии, доступные каналы и постраничная история, безопасные ошибки и общий flood-wait cooldown |
| Каналы | Сохранённые источники по аккаунту, поиск по 100 сообщений, мониторинг с накоплением рекомендаций без автоскачивания |
| Сессия | XChaCha20-Poly1305, атомарный зашифрованный snapshot, ключ в Keychain / Credential Manager, блокировка между процессами |
| Проверки | Модульные тесты, disk-backed SQLite test, тест протокола после перезапуска, GPUI entity tests |
| CI | Нативные сборки, fmt, Clippy и тесты на macOS ARM64 и Windows x64 |

Экран каналов читает **реальные диалоги Telegram**, а экран загрузок —
**настоящую SQLite**, не демонстрационные данные.
Кнопка «Обновить» в каналах обновляет источники; в остальных разделах — историю.
Библиотека показывает записи со статусом `Completed`.
В sidebar отображается `@username` Telegram; при его отсутствии — имя аккаунта.
Профиль получается при входе / проверке сохранённой сессии, не при отрисовке UI,
не попадает в логи и не дублируется в открытой SQLite.
Настройки сохраняют папку загрузок по умолчанию и разрешённые форматы в SQLite.

### Интерфейс по макетам Figma

- **Каналы:** локальный поиск источников и найденных файлов, фильтры формата
  и состояния (новые / в очереди / скачано), таблица с множественным выбором.
  «Выбрать все» действует только на найденные файлы, соответствующие фильтрам.
  Отметки, скрытые фильтром, остаются в общей выбранной группе; её размер
  виден в закреплённой панели. Фильтры не запускают запросы к Telegram.
- **Загрузки:** отдельные вкладки «Очередь» и «История». Активный файл с
  прогрессом, скоростью и ETA показан отдельно от ожидающих заданий.
  Последовательность, отмена и восстановление на паузе не изменены.
- **Библиотека:** самостоятельная таблица сохранённых файлов, поиск по имени /
  источнику, фильтр формата и сортировка. Выберите строку для действий
  «Показать в папке», «Открыть» и копирования пути. Двойной щелчок или Enter
  открывает файл системным приложением; встроенного ридера / распаковки ZIP нет.
- Фильтры открываются мышью или Enter, варианты выбираются стрелками и Enter;
  Escape закрывает меню. В списках работают стрелки, Home / End; Tab переводит
  фокус между элементами. Списки каналов, найденных и скачанных файлов виртуализированы.
- Полное окно по умолчанию — 1280×800. На узком окне канал и список источников
  показаны последовательно; «К списку» возвращает к каналам. В маленьких
  окнах убираются второстепенные колонки / пояснения, sidebar можно скрыть.

Новые загрузки сохраняют исходное имя Telegram **отдельно от безопасного имени
на диске**, название канала и дату начала попытки («Добавлено» в таблице).
Миграция SQLite применяется автоматически, существующая история не удаляется.
Для старых записей сохраняется прежнее имя; если название источника неизвестно,
показывается ID канала. Приложение не выдумывает отсутствующие метаданные
и не сканирует старые сообщения для их восстановления.

### Следующие этапы

- Ручная проверка установленного Windows-пакета, production-подпись и
  нотариализация. Первый выпуск — unsigned Pre-release для такой проверки.

**Пока не реализованы:** параллельность между файлами,
автоматические сетевые повторы и сохранение результатов сканирования между запусками.
Докачка после сбоя / перезапуска выполняется по ручному продолжению очереди.
Источники сохраняются по аккаунту; папка по умолчанию и разрешённые форматы — для приложения.
MemorySession используется только в offline-тесте транспорта; пользовательская
сессия обслуживается собственным write-through адаптером Grammers.
Переключение тем и production-подпись / нотариализация бинарников отложены.
Тестовые пакеты собираются отдельно через cargo-packager; локальная debug-обёртка
`.app` ниже по-прежнему нужна только для разработки.

## Зависимости и воспроизводимость

- Rust **1.98.1 stable**, `rustfmt`, `clippy` — в `rust-toolchain.toml`.
- `gpui` и `gpui_platform` из официального Zed, **одна ревизия**
  [`504abf602a09edc3c7d5a4f4f60958aee335274f`](https://github.com/zed-industries/zed/tree/504abf602a09edc3c7d5a4f4f60958aee335274f).
  Версия Rust совпадает с toolchain этой ревизии.
- На macOS включён `gpui_platform/font-kit`: без него GPUI не отрисовывает текст.
- Grammers **0.11.0**, Tokio **1.54.1**, SQLx **0.9.0**.
- Keyring **3.6.3** с явно включёнными native backend'ами macOS/Windows;
  XChaCha20-Poly1305 **0.11.0**, `getrandom` и `zeroize`.
- Прямые внешние зависимости закреплены через `=version`; Git-зависимости GPUI
  закреплены через `rev`, транзитивные зависимости — через `Cargo.lock`.

Первая сборка загружает зависимости из crates.io и официальных Git-репозиториев
и может занять несколько минут. История и навигация доступны без сети;
авторизация и проверка сохранённой сессии требуют соединения с Telegram.
Используйте `--locked`, не удаляйте `Cargo.lock`.

## Запуск на macOS Apple Silicon

1. Установите Git, [Rust через rustup](https://rustup.rs/) и **полный Xcode**.
   Одних Command Line Tools недостаточно для Metal backend GPUI.
2. Откройте Xcode и завершите установку компонентов, включая Metal toolchain.
3. Проверьте активный Xcode и Metal:

   ```sh
   xcode-select -p
   xcrun --find metal
   ```

   Если выбран только каталог Command Line Tools, переключитесь на установленный
   Xcode: `sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer`.
   На новых версиях Xcode недостающий Metal toolchain можно установить через
   `xcodebuild -downloadComponent MetalToolchain`.

4. В корне репозитория:

   ```sh
   rustup show
   cargo run -p tgbooks-app --locked
   ```

Окно открывается на главном потоке, фоновые операции выполняются на Tokio.
Закрытие последнего окна или `Cmd+Q` завершает приложение и закрывает SQLite.

### Запуск с системными уведомлениями на macOS

`cargo run` запускает отдельный бинарник без bundle identity. macOS не предоставляет
ему `UNUserNotificationCenter`; GPUI безопасно пропускает отправку. Находки и счётчик
при этом работают. Для баннеров закройте предыдущий экземпляр и выполните:

```sh
sh scripts/run-macos.sh
```

Скрипт собирает debug-бинарник с `--locked`, создаёт
`target/dev-bundle/Telegram Books.app` со стабильным bundle ID, подписывает его
локальной ad-hoc подписью и открывает через LaunchServices. Ничего не устанавливается
в `/Applications`, это не установщик и не production-сборка.
`sh scripts/run-macos.sh --build-only` только собирает обёртку.
`TGBOOKS_DATA_DIR` передаётся в новый процесс и позволяет использовать изолированные данные.

Обёртка включает иконку приложения для Dock и системных уведомлений.
В настройках переключатель «Отправлять уведомления» меняет черновик настройки;
изменение применяется после «Сохранить настройки». Кнопка «Тест» находится рядом
и отправляет проверочное уведомление независимо от положения переключателя.

Исходник иконки — `crates/app/resources/branding/app-icon.svg`. Готовые PNG / ICNS /
ICO хранятся в репозитории. Для регенерации после изменения SVG выполните
`cargo xtask icons`: растеризация через закреплённый GPUI, кодирование PNG / ICNS /
ICO — в Rust. Для проверки без замены готовых ресурсов можно выполнить
`cargo xtask icons --output target/icon-check`.
ICNS подключён к macOS-обёртке и тестовому пакету; ICO встроен в Windows-бинарник
как ресурс №1 (его использует GPUI) и в установщик.

## Запуск на Windows 10/11 x64

1. Установите Git for Windows и [Rust через rustup](https://rustup.rs/).
   Используйте toolchain `x86_64-pc-windows-msvc`, не GNU.
2. Установите Visual Studio 2022 Build Tools с workload
   **Desktop development with C++**, MSVC и Windows 10/11 SDK.
3. Откройте PowerShell в корне репозитория:

   ```powershell
   rustup show
   cargo run -p tgbooks-app --locked
   ```

GPUI использует Win32, Direct3D и DirectWrite. Нужен графический сеанс и
совместимый GPU/драйвер. CI проверяет компиляцию и тесты, **не заменяя ручной запуск
на реальной Windows 10/11**.

## Тестовые пакеты без Cargo у пользователя

Упаковка использует **cargo-packager 0.11.8** из официального репозитория CrabNebula
и **cargo-about 0.9.3** для лицензионных уведомлений. Версии инструментов закреплены
в `xtask/packager-version.txt` / `xtask/about-version.txt`; сборка приложения
использует закреплённый Rust и `Cargo.lock`. Это воспроизводимый процесс сборки
с фиксированными версиями, **не гарантия побайтово одинаковых архивов**
(подписи / временные метки могут отличаться).

### Сборка на машине разработчика

Нужны Cargo и native-инструменты из инструкций выше. Дополнительный интерпретатор
не требуется: упаковка и генерация иконок реализованы в Rust workspace-crate `xtask`.
Alias в `.cargo/config.toml` автоматически собирает его через закреплённый Cargo
с `--locked`. Тесты упаковки входят в обычный `cargo test --workspace`.
Пакет собирается на своей ОС: macOS Apple Silicon или Windows x64 MSVC.
Кросс-сборка, Intel macOS и Windows ARM64 не настроены.

На macOS:

```sh
cargo xtask install-tools
cargo xtask package
```

В PowerShell на Windows:

```powershell
cargo xtask install-tools
cargo xtask package
```

Инструменты устанавливаются **только в `target/tools`**, не глобально.
`xtask` проверяет версии, генерирует notices и собирает release без тестовых
GPUI-функций и явно выбирает целевую архитектуру. cargo-packager может загрузить
свои инструменты NSIS при первой Windows-упаковке; пользователю установленного
приложения интернет для установки и Rust не требуются.

Выходные файлы:

- macOS: `target/packages/macos/Telegram-Books-<версия>-aarch64-apple-darwin.zip`
  с `Telegram Books.app` внутри;
- Windows: `target/packages/windows/Telegram-Books-<версия>-x86_64-pc-windows-msvc-setup.exe`
  — NSIS-установщик только для текущего пользователя, без запроса прав администратора;
- рядом с каждым пакетом — файл `.sha256`. Это контрольная сумма для проверки
  целостности, **не подпись издателя**.

macOS-архив создаётся через `ditto`, чтобы сохранить исполняемые права и структуру
`.app`. До архивации проверяются bundle ID, версия из Cargo, иконка, тексты лицензий,
ARM64-архитектура и целостность ad-hoc подписи. Сборка идёт в новую временную папку
под `target/packaging`, поэтому не заменяет уже запущенную debug-обёртку.
Windows release не открывает консоль; manifest включает Per-Monitor V2 DPI,
длинные пути и `asInvoker`, CRT линкуется статически.

### Установка и данные

- macOS: распакуйте ZIP и откройте `.app`. Если приложение находится вне
  `/Applications` и `~/Applications`, оно предложит установку в «Программы».
  Это **не DMG**, копирование без подтверждения пользователя не выполняется.
- Windows: запустите `setup.exe`; установщик предложит папку и ярлыки.
  Удаление приложения не настроено на очистку пользовательских данных.
- Закройте прежний экземпляр перед запуском новой копии. Bundle ID, идентификатор
  системных уведомлений и системные каталоги данных не меняются: история,
  очередь и сессия остаются на своих местах.
- В пакет попадают только бинарник, иконка и явно перечисленные в Cargo
  `LICENSE` / `NOTICE` / `LICENSE-APACHE` / `THIRD_PARTY_NOTICES.txt`. SQLite, Telegram-сессия, ключи,
  `.env`, скачанные книги и каталоги пользователя не упаковываются.

Перед каждой упаковкой `cargo-about --locked --fail` собирает полные лицензионные
тексты для native target, включая транзитивные и build-зависимости. Политика в
`licenses/about.toml` отвергает неизвестные / неразрешённые лицензии. Notices
содержат имена, версии и источники; Git-ревизии доступны также в `Cargo.lock`
исходного архива релиза. При изменении зависимостей нужен повторный review
лицензий; автоматическая проверка не является юридическим заключением.

### Предложение установки на macOS

Упакованная release-версия при запуске вне папок приложений предлагает:

- **«Установить»** — скопировать `.app` в `/Applications`;
- **«Только для меня»** — в `~/Applications`, без автоматического запроса прав
  администратора;
- **«Не сейчас»** — продолжить работу из текущей папки без копирования.

После подтверждения сначала создаётся временная копия в выбранной папке,
проверяется её подпись, затем она публикуется без перезаписи существующего
`Telegram Books.app`. При ошибке исходная копия остаётся на месте, временная
удаляется. Уже установленное приложение, в том числе пустая папка или symlink
с таким именем, не заменяется: при необходимости сделайте замену вручную в Finder.
Исходная копия после успешной установки тоже сохраняется — удалить её можно
вручную после проверки новой.

Приложение перезапускается из установленной копии через GPUI: новый процесс
ожидает завершения старого. До решения об установке backend не открывает
SQLite / Telegram-сессию и не обращается к Keychain. Данные не копируются вместе
с `.app` и продолжают храниться в прежнем системном каталоге.
Подпись и quarantine-атрибуты сохраняются; установка не обходит Gatekeeper.

Проверка учитывает подпапки и symlinks: уже установленная копия в любой из
двух папок не предлагает установку снова. Debug-сборки (`cargo run`,
`run-macos.sh`) и release-запуски без маркера тестового пакета не показывают
этот диалог. С `TGBOOKS_DATA_DIR` диалог также отключён: LaunchServices-перезапуск
GPUI не передаёт произвольные переменные окружения, и профиль тестовых данных
не должен незаметно смениться на обычный.

**Ограничения:** это пакеты для внутренней проверки, не готовый публичный релиз.
macOS-пакет имеет лишь ad-hoc подпись: стабильное доверие Keychain между
пересборками не обещается; нотариализация не выполняется. Windows-пакет
не подписан Authenticode. Gatekeeper / SmartScreen могут предупреждать о неизвестном
издателе. `xtask` не меняет системное доверие и не отключает эти защиты.
Лицензионные уведомления включены в пакеты; для production по-прежнему нужны
подпись издателя и отдельная приёмка на целевых ОС.
Переменные с ключами подписи не используются неявно; загрузка на нотариализацию,
публикация релизов и автообновление в этом этапе отсутствуют.

### CI-артефакты и ручная приёмка

В GitHub Actions workflow **Test packages** запускается вручную через
`workflow_dispatch`, на push веток `release/**` и из release workflow, но не на
каждый обычный push. Он выполняет fmt, Clippy, Rust / GPUI
и тесты `xtask`, собирает native-пакеты на macOS ARM64 и Windows x64, затем
сохраняет пакет и checksum как Actions artifacts на 14 дней.
Workflow не создаёт GitHub Release и имеет только `contents: read`.
Само добавление workflow не означает, что он уже был запущен.

### Первый Pre-release и следующие версии

Workflow **Pre-release** реагирует на push тега `v*`. Он сначала проверяет,
что тег точно соответствует версии `tgbooks-app` из Cargo и существует
`release-notes/<тег>.md`. Затем вызывает сборку обеих native-платформ.
Только после успеха обеих проверяет ровно четыре файла: ZIP, setup.exe и две
SHA-256. Неожиданные файлы, symlinks, неверные имена в checksum и несовпадение
содержимого запрещают публикацию.

Публикация выполняется отдельным job с `contents: write`; build jobs имеют
только `contents: read`. Сначала создаётся draft и загружаются все вложения,
затем он публикуется как **Pre-release**, не `Latest`. При ошибке загрузки
остаётся непубличный draft. Существующий релиз не перезаписывается.
Коммит тега сверяется с коммитом прогона перед созданием и публикацией релиза.
Ручной `Test packages` ничего в Releases не публикует.

Перед первым тегом сохраните все изменения в коммитах отдельной release-ветки,
отправьте её и дождитесь успешного `Test packages`. Это позволяет исправлять
сборку без переписывания версии тега. Для текущей версии:

```sh
cargo xtask check-release v0.1.0
# После проверки commit / CI, не на незакоммиченном рабочем дереве:
GIT_EDITOR=true git tag -a v0.1.0 -m "Telegram Books v0.1.0 pre-release"
git push origin refs/tags/v0.1.0
```

После публикации скачайте Windows `setup.exe` со страницы Releases, а не из
локальной сборки. Теги и вложения опубликованной версии не переписывайте;
для исправления выпускайте следующую версию с новым файлом release notes.

Перед признанием пакета готовым проверьте:

1. Установка / запуск на macOS и на Windows 10/11 без установленного Rust.
2. Иконка, масштабирование окна и отсутствие лишней консоли на Windows.
3. Авторизация, выбор папки, загрузка, перезапуск и докачка.
4. Системное уведомление по кнопке «Тест» и переход в находки.
5. Обновление поверх старой версии и сохранность данных после удаления приложения.
6. Запуск на заявленной минимальной macOS 12.0 — версия согласована с закреплённым
   GPUI, но сборка на новой macOS сама по себе не доказывает совместимость с 12.0.

## Вход в Telegram

1. Получите API ID и API hash приложения на <https://my.telegram.org/apps>.
   Это developer credentials, не токен BotFather.
2. Запустите приложение и в разделе «Вход» введите их в локальные поля.
   **Не присылайте credentials, коды и пароль в чат и не добавляйте в Git.**
3. Разрешите приложению доступ к системному защищённому хранилищу, если ОС
   запросит его. При отказе сессия не сохраняется в открытом виде.
4. Введите телефон с `+` и кодом страны, затем код из Telegram или SMS.
   Способ доставки определяет Telegram, приложение не обещает отправку именно SMS.
5. Если включена 2FA, введите облачный пароль. Вставка из буфера поддерживается.
6. После входа автоматически откроются «Каналы». В разделе «Вход» остаётся
   подтверждение «Telegram подключён». Закройте приложение и запустите снова:
   действующая сессия проверяется без нового кода. Кнопка «Проверить сессию»
   позволяет повторить проверку без перезапуска.

Ошибочный код/пароль можно исправить на том же шаге. При `FLOOD_WAIT` повторные
RPC блокируются локально на указанное Telegram время; cooldown общий для входа,
получения каналов и чтения истории. Автоматических повторов нет.
Запросы входа ограничены 30 секундами. После сетевого сбоя
на 2FA может понадобиться повторно ввести код, чтобы получить новый SRP token.
При ошибке восстановления используйте «Повторить проверку сохранённой сессии»,
чтобы не запрашивать новый код без необходимости.

Grammers 0.11 не поддерживает некоторые ответы входа, например `PaymentRequired`.
Паника этого SDK изолируется в адаптере; UI показывает неподдерживаемый сценарий,
а не закрывает приложение. Регистрация новых аккаунтов не реализуется.

### Что ещё нужно проверить вручную

Offline-тесты используют подменённые Telegram-порт и key store, не реальный
аккаунт. Реальный вход, 2FA и системные разрешения Keychain/Credential Manager
нужно проверить локально со своими credentials. После входа проверьте перезапуск,
отзыв сессии через официальный клиент и повторный вход. Windows дополнительно
требует запуска на реальном графическом сеансе.

## Настройки загрузок

1. Откройте «Настройки», нажмите «Выбрать папку…», отметьте разрешённые форматы
   и нажмите **«Сохранить настройки»**. До подтверждения backend действует прежняя
   конфигурация. При ошибке черновик остаётся в форме для повторной попытки.
2. Первый запуск без сохранённых настроек использует папку `books` в системной
   директории приложения и все шесть форматов. После сохранения значения читаются
   из таблицы `app_settings` в SQLite; миграции не удаляют историю или очередь.
3. Backend проверяет существование папки, канонический путь и реальную возможность
   создать временный файл. Ничего в выбранной папке не перезаписывается.
   Сохранение недоступно во время передачи файла, чтобы проверка сетевого диска
   не задерживала отмену загрузки.
4. Если сохранённая папка исчезла / диск отключён, настройка не сбрасывается молча.
   Приложение запускается; попытка скачивания покажет ошибку и приостановит очередь.
   Восстановите доступ либо удалите задания и добавьте их в другую папку.
   Смена папки по умолчанию **не перемещает файлы и не перенаправляет принятые задания**.
5. Нужно оставить хотя бы один формат. Это настройка обнаружения вложений, а не
   временный фильтр таблицы: открытый канал перечитывает первые 100 сообщений,
   ранее найденные результаты сбрасываются. Библиотека и принятая очередь
   не фильтруются задним числом; прогресс пагинации считает все просмотренные сообщения.

Настройки локальны для установки приложения и не содержат Telegram credentials.
Источники и рекомендации сохраняются отдельно для каждого аккаунта. Мониторинг
включается вручную в «Каналы → Новые книги».

## Каналы и поиск книг

1. После входа / восстановления сессии загружаются каналы из диалогов аккаунта,
   включая каналы без публичного username. Группы и личные чаты не включаются.
   Приложение не ищет чужие каналы, не вступает в них и не помечает сообщения прочитанными.
2. Выберите канал: первые **100 сообщений** загружаются автоматически
   от новых к старым. Поддерживаются PDF, EPUB, FB2, MOBI, DJVU, ZIP
   (расширение без учёта регистра); документы без имени пропускаются.
3. «Ещё 100 сообщений» читает следующую порцию по эксклюзивному message offset.
   Повторный выбор открытого канала не запускает новый запрос и не сбрасывает результаты.
   Видны имя, формат, известный размер, число проверенных сообщений
   и пропущенных защищённых записей. Выбор книги и загрузка описаны ниже.
4. При сетевой ошибке результаты и курсор остаются прежними: повторите действие.
   Если первая порция не загрузилась, нажмите «Повторить загрузку сообщений».
   Получение списка ограничено 60 секундами, одна порция истории — 30 секундами.
   После `FLOOD_WAIT` подождите указанное время и повторите вручную.
5. На узком окне список и содержимое канала показаны последовательно.
   «К списку» возвращает к списку. На широком — оба списка рядом.

### Сохранённые источники

1. Откройте канал и нажмите **«Добавить в источники»**. Это сохраняет выбор,
   но не сканирует остальные каналы и не запускает скачивание.
2. В списке каналов переключите **«Все каналы» → «Мои источники»**.
   Поиск работает и в этом списке, фильтр не обращается к Telegram.
3. После перезапуска восстановятся источники текущего Telegram-аккаунта.
   Открытый канал и позиция сканирования при этом не восстанавливаются.
4. **«Убрать из источников»** удаляет только отметку источника: не выходит из канала,
   не удаляет книги и не меняет принятые задания очереди.
5. Канал, исчезнувший из списка доступных, остаётся в «Моих источниках».
   Его можно убрать или обновить список каналов для проверки доступа.
   При ошибке получения списка доступность показывается как непроверенная.
   Защищённый канал также можно сохранить как источник, но сканирование и скачивание запрещены.
6. Изменения подтверждаются только после записи в SQLite. При ошибке сохранённый выбор
   остаётся прежним; ошибку загрузки можно повторить отдельной кнопкой.

В SQLite хранится ID аккаунта, ID канала и снимок названия / username / признака защиты
на момент добавления. Актуальные данные списка Telegram имеют приоритет над снимком.
Access hash, credentials и сессия в эту таблицу не записываются; сведения об источниках не логируются.

Защита проверяется при получении каналов, повторно через `channels.getChannels`
перед каждой порцией истории и у каждого сообщения/документа.
Каналы с запретом сохранения, сообщения с `noforwards`/ограничениями
и самоуничтожающиеся документы не становятся кандидатами.
Если Telegram отзывает авторизацию, каталог очищается и запускается одна проверка
сессии, без бесконечного цикла запросов. Ошибки API не выводятся в сыром виде.

Каталог и выбранный канал пока живут только в памяти: смена канала сбрасывает
результаты, перезапуск заново получает доступные каналы. Обновление списка сохраняет
выбор/результаты, пока канал остаётся доступным и не защищён.
Дедупликация вложений использует `(channel_id, message_id, document_id)`;
`channel_id` — канонический Bot API dialog ID, не access hash.
На границе ровно 100 сообщений для подтверждения конца истории может потребоваться
ещё одна пустая порция. Ручной поиск не меняет позиции мониторинга.

## Новые книги: мониторинг и рекомендации

1. Сохраните нужные каналы в «Моих источниках», затем откройте **«Новые книги»**
   в заголовке «Каналов» и нажмите **«Включить мониторинг»**.
2. Первая успешная проверка каждого нового источника фиксирует текущую верхнюю
   границу истории, но не предлагает старые книги. Следующие проверки собирают
   новые сообщения после неё, включая сообщения, появившиеся во время выключенного приложения.
   Дата в рекомендации — дата сообщения Telegram, не время локальной проверки.
3. Проверки последовательные: не более 100 сообщений источника за проход,
   пауза 1 секунда между источниками и 60 секунд после полного круга.
   Большой накопившийся промежуток разбирается постранично в следующих кругах,
   без перескока через середину истории. Это политика приложения, не заявленный лимит Telegram.
4. Во время скачивания мониторинг ждёт: проверки идут между файлами.
   Один запрос ограничен 30 секундами. «Выключить мониторинг» применяется после
   текущей проверки; закрытие приложения прерывает работу.
5. Находки накапливаются в SQLite вместе с позицией обработки одной транзакцией.
   Повторная проверка не создаёт дубли и не возвращает скрытые книги.
   Учитываются разрешённые форматы на момент проверки; уже скачанные вложения
   и защищённый контент не предлагаются. Изменения старых сообщений не отслеживаются.
6. Счётчик в sidebar и «Новых книгах» показывает **непросмотренные**, не все находки.
   **«Просмотрено»** меняет только статус; **«Скрыть»** убирает рекомендацию из списка.
   Поиск по имени / каналу и фильтр «Непросмотренные» не обращаются к Telegram.
7. Отметьте одну или несколько строк и нажмите **«Добавить в очередь»** либо `Enter`.
   Только это действие разрешает скачивание в сохранённую папку по умолчанию.
   Очередь остаётся последовательной с обычной защитой от дублей.
   Переход **«К каналу»** открывает обычный просмотр истории выбранного канала.
8. После перезапуска находки, их статусы и позиции сохраняются. Включённый мониторинг
   **возобновляется после восстановления сессии того же аккаунта**; если выключить его
   вручную, он остаётся выключенным. Настройка хранится отдельно для каждого аккаунта.
   При сетевой ошибке, ошибке SQLite,
   отзыве сессии или `FLOOD_WAIT` проверка останавливается; устраните причину и
   включите её снова. Общий cooldown не позволяет обойти ожидание.
   Недоступный / защищённый источник пропускается, остальные продолжают проверяться.

Удаление источника прекращает его мониторинг и удаляет его позицию, но сохраняет
накопленные находки. Повторное добавление начинает новую начальную синхронизацию.
SQLite хранит только локальные метаданные находок, не credentials или access hash.
**Автоматического скачивания нет.**

### Системные уведомления

В **«Настройки → Системные уведомления»** включите отправку и сохраните настройки.
По умолчанию она выключена. ОС запрашивает разрешение при первой отправке;
на macOS используйте `.app`-запуск выше. Рядом с переключателем всегда видна кнопка
**«Тест»** — это разовая проверка даже при активном окне, выключенных автоматических
уведомлениях или несохранённых изменениях. Настройки она не меняет.
При запуске без поддержки системных уведомлений кнопка объясняет, как запустить `.app`.

- Новые находки объединяются в фиксированное окно 5 секунд. Показывается одна сводка
  с количеством книг и каналов, без имён файлов, названий каналов и данных аккаунта.
- При активном окне остаётся только счётчик. Прочитанные, скрытые и уже скачанные
  к моменту отправки находки исключаются. Выключение настройки отменяет ожидающую сводку.
- Нажатие на баннер / «Открыть» активирует окно и раздел «Новые книги», не скачивает файлы
  и не помечает находки просмотренными. Обработчик работает, пока приложение запущено;
  полноценный cold-start запуск по уведомлению не реализован.
- Кандидаты на уведомление — только впервые вставленные строки SQLite. Перезапуск,
  повторная проверка и загрузка истории не создают повторных баннеров.
  Отправка best-effort: при аварии после записи находки, но до передачи события UI,
  баннер может не появиться; сама находка остаётся в списке.
- GPUI не возвращает подтверждение доставки или текущее разрешение ОС. Сохранённая
  галочка означает согласие приложения на отправку, а не гарантию показа.
  Разрешения, режим фокусирования и отключение баннеров контролируются системными настройками.
- Windows использует нативный GPUI toast backend и стабильный AppUserModelID.
  При первой отправке SDK регистрирует отображаемое имя приложения в профиле пользователя.

## Скачивание книг и последовательная очередь

1. Отметьте найденные книги щелчком по строкам либо клавишей `Space`:
   стрелки перемещают курсор, не меняя отметки. «Выбрать все» отмечает все найденные
   книги, включая предыдущие просмотренные страницы, но не неотсканированную историю.
2. Нажмите **«Добавить N в очередь…»** (либо `Enter` в списке книг):
   используется сохранённая папка по умолчанию. «Другая папка…» открывает
   системный диалог macOS / Windows для одной группы и не меняет настройки.
   Одна папка применяется ко всей группе. Без отметок добавляется книга под курсором.
   Отмена диалога ничего не добавляет. Папка должна уже существовать.
3. Книги добавляются в конец FIFO в порядке списка. За одно добавление и в ожидании
   допускается до 256 книг. Недопустимая группа отклоняется целиком; активные,
   ожидающие и завершённые записи с тем же Telegram ID пропускаются со счётчиком повторов.
   Сообщение о пропущенных повторах видно и в «Каналах». Для одной уже скачанной
   книги нижняя панель показывает сохранённый путь, «Показать в папке» и
   **«Скачать повторно…»**. Последнее действие требует явного выбора:
   папка по умолчанию, другая папка или отмена. Смена папки сама по себе не отменяет
   защиту от повторов.
4. Перед началом **каждого** файла приложение заново получает канал и сообщение, проверяет доступ, запрет сохранения,
   TTL / ограничения и совпадение document ID. Изменённое или удалённое вложение
   не подменяется другим файлом.
5. Откроется раздел «Загрузки»: текущий файл, ожидающие задания, проценты,
   переданные байты, прогресс-бар при известном
   размере и кнопка отмены. Для неизвестного размера показываются байты без фиктивного
   процента; окончательный размер определяется в конце.
6. После завершения запись появится и в «Библиотеке». **«Показать в папке»**
   открывает расположение файла в Finder / Explorer, не саму книгу.
7. Закройте и запустите приложение: история начатых загрузок, итоговый путь и статус читаются из SQLite.
   Обычное добавление пропускает завершённые `(channel_id, message_id, document_id)`.
   Явное повторное скачивание в другую папку сохраняет обе копии в истории и библиотеке.
   Существующий файл никогда не перезаписывается; повтор в ту же папку возможен,
   если прежний файл уже перемещён или удалён пользователем.

Одновременно выполняется **одна** загрузка. Выбор нового канала с загрузкой истории,
поиск / обновление каналов и проверка
сессии на время передачи недоступны, чтобы отмена не ждала другого долгого RPC.
Навигация, история, добавление уже найденных книг и отмена остаются доступны.
Переключение выбранного канала не меняет уже принятые задания.
Один сетевой запрос
при подготовке или чтении очередного чанка ограничен 30 секундами.
Прогресс сохраняется / отправляется примерно до четырёх раз в секунду плюс
начало и завершение; маленький файл может сразу перейти с 0 на 100%.

### Скорость и оставшееся время

Справа от названия и прогресса находится колонка фиксированной ширины:
целая скорость (`Б/с`, `КБ/с`, `МБ/с`) сверху и **примерное оставшееся время
текущего файла** снизу, например `400 КБ/с` и `46 мин`. Видимых подписей нет,
но смысл показателей сохранён в доступном имени группы. Выравнивание вправо
и табличные цифры предотвращают сдвиги при смене значений.
Как и размеры в интерфейсе, единицы скорости используют множитель 1024.

- Оценка сглаживается по последним примерно пяти секундам, а не по всей истории
  загрузки. Первая оценка появляется после секунды измерения.
- Worker продолжает измерения, включая ожидание сетевого ответа, раз в секунду.
  **В UI скорость меняется не чаще раза в 10 секунд, ETA — раза в 60 секунд.**
  До первого ненулевого измерения скорости показывается `—`: стартовые нулевые
  heartbeat-оценки не запускают десятисекундный интервал. Первое ненулевое значение
  появляется сразу, после него включается ограничение частоты (в том числе для
  нуля при реальной остановке передачи). Первый доступный ETA также показывается
  сразу. Последующие обновления ограничены независимо друг от друга;
  постоянный поток событий не отодвигает таймер.
- Скорость округляется до целого в выбранной единице. Время округляется вверх
  до целой минуты: для оставшихся 20 секунд показывается `1 мин`.
  От часа оно разбивается на часы и минуты: `155 мин` → `2 ч 35 мин`,
  ровно два часа — `2 ч`. Секунды не показываются.
  Неизвестное значение обозначается `—`. Если ETA становится недостоверной
  при остановке потока, она скрывается сразу, а восстановленная оценка ждёт
  своего минутного обновления, чтобы не мигать.
- При неизвестном полном размере скорость видна, но оставшееся время — `—`.
  Когда все байты получены, статус меняется на «Сохраняем файл…».
  ETA не включает ожидание в очереди, авторизацию, flood-wait или финальную
  синхронизацию и публикацию файла.
- Метрики вычисляются в worker по монотонному времени и передаются в GPUI
  типизированными событиями через Core. Они не сохраняются в SQLite и сбрасываются
  при повторе, отмене, завершении и запуске следующего файла.
  Пересчёт сам по себе не делает Telegram-запросов и не записывает БД.

**Почему счётчик растёт порциями по 0,5 МБ:** `DownloadIter` в Grammers 0.11
использует части по 512 KiB (524 288 байт), это его стандартный и максимальный
размер части. Это **не лимит скорости 0,5 МБ/с**.
[Telegram допускает download-запросы до 1 MiB с ограничениями выравнивания](https://core.telegram.org/api/files#downloading-files),
а [Grammers ограничивает `chunk_size` до 512 KiB](https://docs.rs/grammers-client/0.11.0/grammers_client/client/struct.DownloadIter.html#method.chunk_size).
Наш потоковый сценарий запрашивает части последовательно и не содержит
искусственного sleep / ограничения байтов в секунду. Задержки RPC, сеть,
ограничения аккаунта и запись на диск влияют на фактическую скорость.
Показатели скорости и ETA не ускоряют передачу: перекрытие запросов частей
одного файла — отдельная оптимизация; параллельность между книгами не добавлена.

### Управление очередью и ошибки

- «Приостановить очередь» не прерывает текущий файл: после него следующий не запускается.
  «Продолжить очередь» разрешает запуск следующего задания.
- «Убрать из очереди» удаляет только ожидающее задание, без открытия файла в Telegram.
  Отмена текущей загрузки не отменяет остальные: запускается следующая книга.
- Сетевой сбой сохраняет задание в начале очереди и приостанавливает её.
  Проверьте соединение и нажмите «Продолжить очередь»: скачанная часть будет
  проверена и использована для докачки.
  Удалённое вложение, запрет сохранения, несовпадение размера или
  конфликт файла завершают отдельное задание; очередь переходит к следующему.
  Последняя ошибка с именем книги остаётся видна до нового добавления / продолжения.
- `FLOOD_WAIT` приостанавливает всю очередь и включает общий cooldown.
  После указанного ожидания нажмите «Продолжить очередь»; раннее нажатие не отправляет
  RPC и показывает оставшееся время. Неудавшееся задание остаётся в очереди.
  Автоматических сетевых повторов нет.
- Ошибка SQLite, защищённого хранилища или непредвиденное завершение worker также
  приостанавливают очередь. При потере авторизации задания скрываются из текущего UI;
  сохранённая очередь остаётся привязана к исходному аккаунту и не запускается
  под другим пользователем.

### Восстановление очереди после перезапуска

1. Добавьте несколько книг и выберите папку. Порядок, Telegram ID, имена,
   форматы, размеры и папки назначений сохраняются в `download_queue` внутри SQLite.
2. Закройте приложение с ожидающими заданиями или активной загрузкой.
3. После запуска и успешного восстановления авторизации очередь появится
   **на паузе** с сообщением «Очередь восстановлена». Загрузка не начинается автоматически,
   независимо от состояния паузы перед закрытием.
4. Ранее начатое задание находится в начале списка и отмечено
   **«Прервано · Доступна проверка и докачка»**. Нажмите «Продолжить очередь»
   либо удалите ненужное задание. Повторно сканировать ту же страницу канала не нужно.
5. При продолжении каждый файл снова проходит проверки доступа, document ID
   и защиты контента. Прерванный файл продолжается с последней подтверждённой
   контрольной точки. Скорость измеряется только по новым байтам,
   ETA учитывает уже скачанную часть.
6. Завершённые и успешно отменённые задания повторно не восстанавливаются.
   Сетевые / системные ошибки сохраняют задание на паузе, но не запускают
   бесконечный автоматический повтор. Закрытие приложения и явная отмена — разные действия.

Сохранение — атомарная замена снимка очереди в транзакции. Допуск группы и удаление
задания подтверждаются UI только после записи. Перед первым запросом файла
сохраняется отметка начатого задания, поэтому восстановление не зависит от того,
успел ли выполниться quit hook. При ошибке записи очередь приостанавливается,
изменение не выдаётся за сохранённое. Если прочитать очередь не удалось,
она не перезаписывается пустой; после устранения проблемы нажмите «Обновить».
Если не загрузился список каналов, обновите его в «Каналах», затем продолжите очередь:
неудачный startup-запрос не должен удалять все сохранённые задания как недоступные.

Очередь разделена по числовому ID аккаунта, взятому из зашифрованного self-peer
сессии Grammers после авторизации. Телефон, API credentials, ключи MTProto и access hashes
в таблицу очереди не попадают. Сама SQLite, как и история, **не зашифрована**.
История `Completed` имеет приоритет над устаревшей отметкой активного задания.
При восстановлении допускается 257 записей: один прерванный файл и до 256 ожидающих;
новое добавление по-прежнему ограничено 256 ожидающими книгами.

Миграция `0002_download_queue.sql` применяется автоматически и не меняет старую
историю. Задания, созданные в старой версии, где очередь жила только в памяти,
восстановить задним числом невозможно. Для новых загрузок миграция
`0009_download_checkpoints.sql` сохраняет путь `.part`, исходное имя / размер,
смещение, SHA-256 префикса и отметку проверенного EOF. Части от старых версий
без контрольной точки использовать нельзя; приложение не удаляет такие файлы автоматически.

### Проверка докачки

1. Начните загрузку большого файла и дождитесь ненулевого прогресса.
2. Закройте приложение (не нажимайте «Отменить загрузку») и запустите его снова.
3. В «Загрузках» продолжите восстановленную очередь. Перед записью приложение
   перечитает сохранённый префикс и проверит SHA-256; на большом файле это может
   занять некоторое время. Прогресс продолжится с проверенного смещения.
4. Для проверки сети отключите соединение на время запроса. После таймаута
   очередь останется на паузе; восстановите сеть и продолжите вручную.
5. Убедитесь, что итоговый файл открывается и не содержит повторённого префикса.

Файл и SQLite не обязаны успеть записаться одновременно: приложение сначала
синхронизирует данные, затем фиксирует смещение и хеш. Лишний хвост после сбоя
отсекается до контрольной точки. Если часть отсутствует, усечена, повреждена
или не соответствует свежим метаданным, загрузка безопасно начинается с нуля.
Хеш защищает от случайного повреждения локальной части, но не является
предоставленной Telegram контрольной суммой всего удалённого файла.

### Файлы, ошибки и ограничения

- Данные читаются чанками до 512 KiB, не целиком в память. Части записываются во
  временный `.tgbooks-*.part` **в выбранной папке**, затем выполняются flush / sync
  и проверка фактической длины.
- Итоговое имя: `book-<очищенное имя>--<channel_id>-<message_id>-<document_id>.<формат>`.
  Части пути, Windows-reserved символы, управляющие / bidi-символы удаляются или
  заменяются, длина ограничивается. Префикс исключает Windows device names,
  ID различают одноимённые вложения. ZIP не распаковывается.
- Публикация использует `persist_noclobber`: существующий файл, каталог или symlink
  не заменяются, включая гонку с другим процессом. Выберите другую папку или
  переместите прежний файл вручную. Не удаляйте свои файлы без проверки.
- Сетевая ошибка сохраняет `.part` и контрольную точку; явная отмена и несовпадение
  размера удаляют незавершённую часть. В истории остаётся статус `Failed`.
  «Убрать из очереди» для прерванного задания также удаляет его частичный файл,
  но не готовые книги. Если папка недоступна, задание всё равно можно убрать,
  а ошибка очистки показывается в UI; недоступная часть остаётся на диске.
  Ошибки подготовки до создания задания могут не иметь записи в истории.
- После перезапуска `Queued` / `Downloading` переводятся в `Failed`, а не выдаются
  за продолжающиеся загрузки. Данные не докачиваются автоматически.
- SQLite и файловая система не образуют одну транзакцию. Авария или ошибка БД
  между публикацией и фиксацией `Completed` может оставить полноценный файл без
  завершённой записи. При продолжении его размер и SHA-256 сверяются с контрольной
  точкой проверенного EOF: совпавший файл отмечается завершённым без повторной
  передачи. Другой существующий файл не перезаписывается.
  При аварии в момент создания временного файла может остаться `.part` без
  контрольной точки; такие посторонние части автоматически не удаляются.
- Отмена после начала публикации может закончиться успешным `Completed`:
  этот короткий участок не прерывается обычной отменой. При закрытии приложения
  worker прерывается с сохранением последней контрольной точки, а не получает
  пользовательскую отмену с удалением частичного файла.
- История не проверяет существование / целостность файла после ручного перемещения
  или удаления. Завершённая запись по-прежнему исключает обычное добавление;
  для восстановления файла используйте «Скачать повторно…» в «Каналах».
  Подробная последняя ошибка показывается в текущем сеансе; в БД сохраняется статус.

## Локальные данные и безопасность

Путь определяется `directories::ProjectDirs` с идентификаторами
`org / tgbooks / TelegramBookDownloader`:

- macOS: `~/Library/Application Support/org.tgbooks.TelegramBookDownloader/`.
- Windows: `%LOCALAPPDATA%\tgbooks\TelegramBookDownloader\data\`.

Точный путь виден в разделе «Настройки». Внутри находятся:

- `downloads.sqlite3` (включая служебные WAL/SHM-файлы SQLite) и директория `books`;
- `telegram.session.enc`: credentials и состояние MTProto в зашифрованном виде;
- `telegram.session.lock`: несекретный файл блокировки. Наличие файла не означает,
  что приложение запущено; блокировка удерживается открытым дескриптором.
  Не удаляйте его, пока приложение работает.
- `tgbooks.app.lock`: отдельная блокировка каталога **до открытия БД и recovery**.
  Второй экземпляр не меняет историю активного первого экземпляра.
  Наличие оставшегося файла само по себе не является активной блокировкой.

На Unix новые директории создаются с mode `0700`; права уже существующих
директорий не меняются. На Windows используются унаследованные системные ACL.
**История не зашифрована и не предназначена для хранения секретов.**

Сессия шифруется XChaCha20-Poly1305 с новым случайным 24-байтовым nonce на каждый
snapshot. На диск сначала записывается и синхронизируется только ciphertext,
затем файл заменяется атомарно. Изменения ключей MTProto подтверждаются Grammers
лишь после записи: сохранение не зависит от quit hook.
Снимки версионированы и ограничены 16 MiB. Некорректный файл, отсутствие ключа,
ошибка доступа или занятая сессия приводят к отказу, а не plaintext fallback.

В системном хранилище лежит только случайный 32-байтовый ключ.
Service: `org.tgbooks.TelegramBookDownloader`; account — SHA-256 канонического
пути директории данных. Ключ не экспортируется вместе с файлом сессии:
перенос/переименование директории или копирование на другой компьютер не является
переносом авторизации. Управление и возможный roaming системного vault определяются
политиками ОС (в частности, Windows Credential Manager).
Если ключ утрачен, приложение не перезаписывает существующую сессию: восстановите
соответствующую пару ключ/файл либо задайте новую директорию данных для нового входа.
Защита не рассчитана на компрометацию самой ОС или память работающего процесса.

Для разработки можно явно направить все данные в игнорируемый `target`:

```sh
TGBOOKS_DATA_DIR="$PWD/target/dev-data" cargo run -p tgbooks-app --locked
```

```powershell
$env:TGBOOKS_DATA_DIR = Join-Path (Get-Location).Path "target\dev-data"
cargo run -p tgbooks-app --locked
```

`TGBOOKS_DATA_DIR` должен быть абсолютным путём. Файлы данных не создаются
относительно текущей директории неявно.

- Не добавляйте API ID/hash, номер телефона, коды, пароли и сессии в Git,
  исходники, снимки тестов или логи.
- `.env`, session-файлы, SQLite и логи исключены через `.gitignore`.
  Само приложение **не загружает `.env`**: credentials вводятся в UI.
- `ApiCredentials`, команды входа и секретные строки имеют redacted `Debug`.
  Собственные буферы секретов и ключа очищаются через `zeroize`; это не гарантия
  удаления всех копий из памяти сторонних библиотек.
- Код и пароль не сохраняются в сессию. Поля API hash и 2FA скрыты в отрисовке,
  accessibility value и IME readback; их копирование/вырезание запрещено,
  вставка разрешена. После отправки код и пароль удаляются из полей.
- Логируются только собственные targets `tgbooks`, `tgbooks::*`, `tgbooks_*`
  на уровне INFO и выше.
  `RUST_LOG` намеренно не включает подробные логи зависимостей/MTProto.
  SQL statement logging выключен.
- Внешние ошибки не передаются в UI в сыром виде: используются типизированные
  безопасные категории ошибок.
- Никакого обхода protected content: Telegram-адаптер исключает такой контент
  из каталога, Core блокирует сканирование защищённых каналов, очередь отклоняет
  защищённые кандидаты. Перед передачей проверяются свежие канал и сообщение.

```text
crates/
  app/          composition root, Tokio lifecycle, GPUI views и platform UI choices
  core/         модели, actor, команды/события, auth/catalog/source/engine/repository ports
  telegram/     Grammers, защищённая сессия и OS key store; не экспортируются в GPUI views
  downloader/   потоковая запись, безопасные пути, публикация, правила допуска и FIFO
  storage/      SQLx, миграции, системные директории, блокировка данных
xtask/          developer tooling: упаковка, проверка пакетов и генерация иконок
```

`xtask` не входит в установленное приложение и не зависит от его Core / Telegram /
Storage. Он вызывает Cargo, закреплённый packager и системные инструменты упаковки;
для растеризации SVG запускает отдельный dev-режим GPUI без backend / сессии.

Направление зависимостей: `app → core/storage/telegram/downloader`, `storage → core`,
`telegram → core`, `downloader → core`. Telegram подключён через
`Authentication`, `ChannelCatalog`, `BookSource` / `BookChunks`.
`LocalDownloader<Storage>` реализует `DownloadEngine` и пишет состояния через
`DownloadRepository`; зависимости от SQLx или Grammers у Downloader нет.
Намерения очереди Core читает / записывает через `QueueStore`, реализованный Storage;
порядок и пауза не зависят от существования файла в истории.
Core не зависит от GPUI, SQLx, Grammers или platform-specific API.

```text
GPUI view
  → CoreCommand через bounded async-channel (без блокировки UI)
  → application service на Tokio
  → DownloadHistory port → SQLx adapter / Authentication + ChannelCatalog → Grammers + encrypted Session
  → QueueStore port → атомарный SQLite-снимок намерений очереди по ID аккаунта
  → BookSource → owned BookChunks → DownloadEngine → файловая система + DownloadRepository
  → CoreEvent через bounded async-channel
  → GPUI Context::spawn → Entity::update → Context::notify
```

Миграции встроены в бинарник через `sqlx::migrate!`; `storage/build.rs` отслеживает
добавление SQL-файлов на stable Rust. `.gitattributes` фиксирует LF, чтобы хеши
миграций совпадали на обеих ОС. SQLx CLI, внешняя БД и `DATABASE_URL` не нужны.
Идентичность вложения — `(channel_id, message_id, document_id)`, а не имя файла.
История различает локальные копии по этой тройке и `local_path` (SQLite primary key).
Обычное добавление по-прежнему исключает завершённое вложение независимо от папки;
обойти только эту проверку можно явным действием «Скачать повторно…».
Скачивание одного документа из разных сообщений пока считается разными записями.

## Проверки

Из корня репозитория:

```sh
cargo fmt --all -- --check
cargo build --workspace --locked
cargo clippy --workspace --all-targets --all-features --locked -- -D warnings
cargo test --workspace --all-features --locked
```

GPUI tests включаются feature `gpui-tests`; стандартный `cargo test --workspace --locked`
запускает обычные unit/integration tests без этой дополнительной инфраструктуры.

Для визуальной проверки на macOS можно отрисовать все экраны через настоящий
Metal renderer с системным шрифтом, не запрашивая захват рабочего стола:

```sh
cargo run -p tgbooks-app --features gpui-tests --locked -- --render-ui-preview
```

PNG сохраняются в `target/ui-previews` (или `TGBOOKS_PREVIEW_DIR`).
Это opt-in инструмент разработки: он использует вымышленные каналы, вложения
и состояния загрузок (включая unknown-size, ошибку и завершение) для превью,
не открывает SQLite и не подключается к Telegram. Нативные кнопки macOS
в PNG не попадают: они добавляются AppKit поверх GPUI.
Windows-превью пока не поддерживается renderer'ом закреплённого GPUI.

Тесты не требуют Telegram-аккаунта, credentials или сервера:

- Core: расширения, сериализация, корректность прогресса, протокол команд,
  state machine авторизации, общий cooldown, безопасные ошибки и отмена активного RPC;
  автозагрузка каналов после входа, пагинация, повтор после ошибки, защита и отзыв сессии.
  Загрузки: запрет до входа / для неизвестных ключей, смена защиты, общий cooldown,
  прогресс и отмена при работе actor; FIFO групп, атомарный допуск и граница 256,
  добавление во время работы, дубликаты, пауза, отмена ожидающего / активного задания,
  продолжение после ошибки, запрет параллельных файлов и очистка при отзыве сессии.
  Сохранённая очередь: ручное продолжение после восстановления, порядок и папки,
  прерывание / явная отмена, привязка к аккаунту, отказ записи / чтения без потери намерений.
  Метрики: разогрев, скользящая скорость, остановка / восстановление потока,
  неизвестный размер, большие ZIP и защита от переполнений.
- Downloader: FIFO, дубликаты в очереди и в работе, идентичные message ID в
  разных каналах, отклонение protected content; реальные файлы на подменённом потоке,
  Unicode-папки, неизвестная / нулевая длина, сетевой обрыв, неполный файл,
  отмена, безопасные имена, no-clobber гонка, symlink (Unix), ошибки SQLite.
  Heartbeat при заблокированном чтении не отменяет и не пересоздаёт текущий
  chunk future, после ожидания сохраняются правильные байты.
  Докачка: точное смещение после повторного открытия SQLite, SHA-256 префикса,
  отсечение неподтверждённого хвоста, повреждённая / отсутствующая часть,
  изменившийся размер и запрет чтения / удаления файлов за пределами папки.
- Storage: реальные временные SQLite-файлы, миграции, повторное открытие,
  Unicode-пути, атомарный claim / retry, неизменность завершённых записей, recovery,
  проверка диапазонов чисел и эксклюзивная блокировка каталога.
  Обновление БД с первой миграции без потери истории, ordered roundtrip очереди,
  разделение аккаунтов, rollback после частичной записи, испорченные данные,
  приоритет завершённой истории и предел 257 записей.
  Контрольные точки: отказ записи не заменяет валидное смещение; фиксация
  `Completed` и удаление контрольной точки откатываются одной транзакцией.
- App: полный offline-сценарий через Core с fake Telegram, промежуточный прогресс 50%, скорость / ETA,
  реальные байты на диске и история после повторного открытия БД; ошибки путей.
  Группа из трёх книг с ошибкой второй: первая / третья сохраняются, повтор после
  перезапуска пропускает завершённые записи без создания дубликатов.
  Прерывание реального потока после 50% → повторное открытие SQLite → очередь на паузе →
  ручное продолжение с сохранённого смещения → точное содержимое двух файлов,
  без дубликатов и оставшихся `.part`.
- GPUI: состояние entity, навигация и получение асинхронных событий без Tokio
  на UI-потоке; вход через native input/Tab/Enter, UTF-16/IME, Unicode-удаление,
  маскирование и clipboard policy; клавиатурный выбор среди 1000 каналов,
  прокрутка виртуального списка, переход к каналу и возврат на узком окне;
  выбор / отмена системного диалога через GPUI test platform, запуск одной команды,
  обновление прогресса и отмена клавиатурой; множественный выбор в порядке каталога,
  добавление при активной загрузке, пауза / удаление ожидающего задания и отсутствие
  перехвата навигации при запуске следующего файла.
  Показатели измерения / ожидания / сохранения; поздние метрики не возвращаются
  на завершённую загрузку и не восстанавливаются из истории.
- Telegram: ciphertext roundtrip, случайный nonce, подмена файла, потеря ключа,
  отказ vault, межпроцессная блокировка, write-through ключей/peers/update state
  и rollback при ошибке записи; пакетное сохранение peers и пропуск идентичных snapshots;
  запрет discovery / download до входа; ни одного реального сетевого запроса.

Очистка backend зарегистрирована в `on_app_quit`, а не только после возврата
event loop: на macOS AppKit может завершить процесс, не возвращая управление
в `main`. У закреплённого GPUI бюджет quit hooks — 200 мс.
Отдельный cancellation token прерывает активную авторизацию или discovery, не дожидаясь
команды в очереди; блокирующая запись удерживает session lock до завершения.
Для явной отмены file worker есть собственный token; quit делает abort / join,
сохраняя последнюю контрольную точку для докачки.
Снимки сохраняются при изменениях, не только при закрытии окна.

Для работы только над неграфическими crate (в том числе на Linux):

```sh
cargo test -p tgbooks-core -p tgbooks-downloader -p tgbooks-storage -p tgbooks-telegram --locked
```

Полная Linux UI-сборка не входит в целевые платформы и не настроена.
GitHub Actions запускает полный набор проверок на `macos-15` (ARM64) и
`windows-2022` (x64). Основной CI ничего не публикует и не подписывает.
Отдельный вручную запускаемый `Test packages` сохраняет только тестовые
архивы / установщики и их checksum как Actions artifacts.
